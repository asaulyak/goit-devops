# Lesson 5: Terraform Infrastructure для AWS

Цей проєкт містить Terraform конфігурацію для створення інфраструктури AWS, включаючи:
- S3 бакет та DynamoDB для зберігання та блокування стейт-файлів Terraform
- VPC з публічними та приватними підмережами
- ECR репозиторій для зберігання Docker-образів

## Структура проєкту

```
lesson-5/
│
├── main.tf                  # Головний файл для підключення модулів
├── backend.tf               # Налаштування бекенду для стейтів (S3 + DynamoDB)
├── variables.tf             # Загальні змінні проєкту
├── outputs.tf              # Загальне виведення ресурсів
│
├── modules/                 # Каталог з усіма модулями
│   │
│   ├── s3-backend/          # Модуль для S3 та DynamoDB
│   │   ├── s3.tf            # Створення S3-бакета
│   │   ├── dynamodb.tf     # Створення DynamoDB
│   │   ├── variables.tf     # Змінні для S3
│   │   └── outputs.tf       # Виведення інформації про S3 та DynamoDB
│   │
│   ├── vpc/                 # Модуль для VPC
│   │   ├── vpc.tf           # Створення VPC, підмереж, Internet Gateway
│   │   ├── routes.tf        # Налаштування маршрутизації
│   │   ├── variables.tf     # Змінні для VPC
│   │   └── outputs.tf       # Виведення інформації про VPC
│   │
│   └── ecr/                 # Модуль для ECR
│       ├── ecr.tf           # Створення ECR репозиторію
│       ├── variables.tf     # Змінні для ECR
```

## Модулі

### 1. Модуль s3-backend

Модуль для створення S3-бакета та DynamoDB таблиці для зберігання та блокування стейт-файлів Terraform.

**Особливості:**
- S3-бакет з увімкненим версіюванням для збереження історії стейтів
- Шифрування на стороні сервера (SSE-S3)
- Блокування публічного доступу
- DynamoDB таблиця для блокування стейтів (запобігає одночасним змінам)

**Ресурси:**
- `aws_s3_bucket` - S3-бакет для стейт-файлів
- `aws_s3_bucket_versioning` - Версіювання для S3-бакета
- `aws_s3_bucket_server_side_encryption_configuration` - Шифрування
- `aws_s3_bucket_public_access_block` - Блокування публічного доступу
- `aws_dynamodb_table` - Таблиця для блокування стейтів

### 2. Модуль vpc

Модуль для створення VPC з публічними та приватними підмережами.

**Особливості:**
- VPC з налаштованим CIDR блоком
- 3 публічні підмережі в різних зонах доступності
- 3 приватні підмережі в різних зонах доступності
- Internet Gateway для публічних підмереж
- NAT Gateway для приватних підмереж (по одному на приватну підмережу)
- Налаштування маршрутизації через Route Tables

**Ресурси:**
- `aws_vpc` - Віртуальна приватна хмара
- `aws_subnet` - Підмережі (публічні та приватні)
- `aws_internet_gateway` - Internet Gateway
- `aws_eip` - Elastic IP для NAT Gateway
- `aws_nat_gateway` - NAT Gateway
- `aws_route_table` - Таблиці маршрутизації
- `aws_route_table_association` - Прив'язка підмереж до таблиць маршрутизації

### 3. Модуль ecr

Модуль для створення ECR репозиторію для зберігання Docker-образів.

**Особливості:**
- ECR репозиторій з автоматичним скануванням образів при push
- Політика життєвого циклу для автоматичного видалення старих образів (зберігає останні 10)
- Політика доступу для репозиторію
- Шифрування образів

**Ресурси:**
- `aws_ecr_repository` - ECR репозиторій
- `aws_ecr_lifecycle_policy` - Політика життєвого циклу
- `aws_ecr_repository_policy` - Політика доступу

## Передумови

1. Встановлений Terraform (версія >= 1.0)
2. Налаштовані AWS credentials (через `aws configure` або змінні оточення)
3. AWS CLI встановлений та налаштований

## Використання

### 1. Ініціалізація проєкту

```bash
terraform init
```

Ця команда завантажить необхідні провайдери та ініціалізує бекенд.

**Важливо:** Перед першим запуском потрібно створити S3-бакет та DynamoDB таблицю вручну, або використати окремий Terraform проєкт для їх створення, оскільки бекенд потребує їх існування.

### 2. Перегляд плану змін

```bash
terraform plan
```

Ця команда покаже всі ресурси, які будуть створені, змінені або видалені.

### 3. Застосування змін

```bash
terraform apply
```

Ця команда створить всі ресурси в AWS. Підтвердіть виконання, ввівши `yes`.

### 4. Перегляд вихідних даних

Після успішного застосування, ви можете переглянути вихідні дані:

```bash
terraform output
```

### 5. Видалення інфраструктури

```bash
terraform destroy
```

Ця команда видалить всі створені ресурси. Підтвердіть виконання, ввівши `yes`.

## Змінні

Основні змінні проєкту (можна перевизначити через `terraform.tfvars` або змінні оточення):

- `aws_region` - AWS регіон (за замовчуванням: `us-west-2`)
- `bucket_name` - Ім'я S3-бакета (за замовчуванням: `goit-devops-terraform-state`)
- `table_name` - Ім'я таблиці DynamoDB (за замовчуванням: `terraform-locks`)
- `vpc_cidr_block` - CIDR блок для VPC (за замовчуванням: `10.0.0.0/16`)
- `public_subnets` - CIDR блоки для публічних підмереж
- `private_subnets` - CIDR блоки для приватних підмереж
- `availability_zones` - Зони доступності
- `vpc_name` - Ім'я VPC (за замовчуванням: `lesson-5-vpc`)
- `ecr_name` - Ім'я ECR репозиторію (за замовчуванням: `lesson-5-ecr`)
- `scan_on_push` - Автоматичне сканування образів (за замовчуванням: `true`)

## Вихідні дані

Проєкт виводить наступну інформацію:

- **S3 та DynamoDB:**
  - `s3_bucket_name` - Ім'я S3-бакета
  - `s3_bucket_arn` - ARN S3-бакета
  - `dynamodb_table_name` - Ім'я таблиці DynamoDB

- **VPC:**
  - `vpc_id` - ID VPC
  - `vpc_cidr_block` - CIDR блок VPC
  - `public_subnet_ids` - ID публічних підмереж
  - `private_subnet_ids` - ID приватних підмереж
  - `internet_gateway_id` - ID Internet Gateway
  - `nat_gateway_ids` - ID NAT Gateway

- **ECR:**
  - `ecr_repository_url` - URL репозиторію ECR
  - `ecr_repository_arn` - ARN репозиторію ECR

## Важливі зауваження

1. **Бекенд S3:** Перед першим запуском `terraform init` переконайтеся, що S3-бакет та DynamoDB таблиця вже існують, або створіть їх окремо.

2. **Витрати:** NAT Gateway та Elastic IP є платними ресурсами. Врахуйте це при тестуванні.

3. **Регіон:** За замовчуванням використовується регіон `us-west-2`. Змініть його у змінних, якщо потрібно.

4. **ECR політика доступу:** За замовчуванням політика дозволяє доступ для всіх. Налаштуйте її відповідно до ваших потреб безпеки.
